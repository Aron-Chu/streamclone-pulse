Design provenance & architecture notes

Colors, type, the SH panel-header pattern, ConfBar, Pill, and the MomentsTable / Inspector / ChannelsTable / CoveragePanel / EmotePanel layouts were pulled 1:1 from the connected Figma Make file (StreamPulse Analytics Page Redesign, fileKey C35yDLsXdkoRyDvnlxd5gr) via get_design_context → src/app/App.tsx. The slate token set (--bg, --accent, --green, --cyan, --amber, --red, …), the mock moment/emote/channel data, and the gaussian-bump chart generator are copied verbatim from that source so this mock is pixel- and data-accurate to what's in Figma — not a reinterpretation.

What changed vs. the literal Figma layout

  • Top emote bursts moved beside the chart (was stacked under the Inspector in the default grid) and made clickable — clicking an emote plots a synthetic burst line for that exact emote on the chart and jumps the Inspector to its matching moment.
  • Most reacted minutes emote chips and the VOD pill are now real interactive affordances: the emote links out to 7TV, the VOD pill (when synced/partial) jumps to that timestamp — the static Figma mock only painted these as colored text.
  • Channel identity in the session header links to Twitch; clicking a row in Live sessions is intentionally inert here (no multi-channel routing in this static mock) rather than faked.

Wiring for production

  • Chart traces (chatN/viewersN/emotesN/sentimentN/heat) map to the same normalized signal fields already used by GlobalActivityChart — swap the synthetic STREAM_DATA generator for the real per-minute series from /v1/public/hub.
  • The emote-plot overlay needs a real per-minute emote series (provider emote counts bucketed by minute) — currently approximated with a gaussian bump centered on each emote's peak minute, matching only count/peak, not a true timeline.
  • livePulseMomentsStatus/reason should still drive the fallback banner above this section when feed.source !== "network" — this mock assumes a healthy network-live state throughout.
